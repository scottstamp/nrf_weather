# Firmware

Zephyr app in `firmware/`, built with nRF Connect SDK v3.4.2 (Zephyr 4.4.2). BLE controller is the Nordic SoftDevice Controller (`CONFIG_BT_LL_SOFTDEVICE`).

## Build and flash

```sh
source scripts/ncs-env.sh            # west + Zephyr SDK from the NCS toolchain bundle (no nrfutil needed)
cd firmware
west build -b promicro_nrf52840/nrf52840/uf2 -d build .                                   # release
west build -b promicro_nrf52840/nrf52840/uf2 -d build-debug . -- -DEXTRA_CONF_FILE=debug.conf  # USB log
# clones without 32 kHz crystal: add rc_lfclk.conf, e.g. -DEXTRA_CONF_FILE="rc_lfclk.conf"
```

**Bootloader without SoftDevice** (ProMicro clones whose `INFO_UF2.TXT` says "SoftDevice: not found", including the board used in bring-up): the bootloader starts the app at 0x1000, so add the partition overlay. Without it the app is linked at 0x26000 and never runs:

```sh
west build -b promicro_nrf52840/nrf52840/uf2 -d build . -- -DEXTRA_DTC_OVERLAY_FILE=boards/uf2_no_softdevice.overlay
west build -b promicro_nrf52840/nrf52840/uf2 -d build-debug . -- -DEXTRA_CONF_FILE=debug.conf -DEXTRA_DTC_OVERLAY_FILE=boards/uf2_no_softdevice.overlay
```

Output: `build/firmware/zephyr/zephyr.uf2`. NCS builds with sysbuild by default, so the image sits in a subfolder named after the app directory.

To flash, double-tap RESET on the nice!nano. A `NICENANO` USB drive appears; copy `zephyr.uf2` onto it. The board reboots into the app.

Debug build: logs go to the USB CDC ACM console, e.g. `screen /dev/ttyACM0`. The debug build polls every 5 min and goes stale after 20 min, to make bench testing quicker.

Sizes at v0.1.0:

| Build | Flash | RAM |
|-------|-------|-----|
| release | 130 KB | 50 KB |
| debug | 210 KB | 61 KB |

## Source map

| File | Role |
|------|------|
| `src/main.c` | State machine: battery → poll → refresh decision → sleep. Watchdog. |
| `src/wx_service.c` | Advertising, connection handling, GATT service per `docs/protocol.md`. Receive buffer, CRC check. |
| `src/epd_ssd1680.c` | Tri-colour SSD1680 driver. Panel power and pin release. |
| `src/framebuf.c` | Two-plane framebuffer in protocol format. Landscape drawing helpers for the device's own overlays. |
| `src/font_gen.h` | 20 px DejaVu Sans Bold subset, generated by `scripts/gen_font.py`. |
| `src/battery.c` | SAADC VDDH/5 one-shot read and LiPo % curve. |
| `dts/bindings/wx,ssd1680-bwr.yaml` | Panel binding: spi-bus phandle plus cs, dc, reset, busy and power GPIOs. |
| `boards/promicro_nrf52840_nrf52840_uf2.overlay` | Pin map, SPIM2, ADC channel, peripherals disabled. |

## Why not Zephyr's `ssd16xx` driver

Zephyr's `ssd16xx` driver (and the `solomon,ssd1680` binding) only supports `PIXEL_FORMAT_MONO10`. It uses the RED RAM (`0x26`) as the "previous frame" buffer for partial refresh, so the red plane can't be driven. It also puts CS under SPI-driver control, which conflicts with disconnecting every pin while panel power is off.

The app driver uses SPIM with a zeroed `spi_config.cs` and drives CS as a plain GPIO.

## Panel sequence (SSD1680, B/W/R, 128x296)

```
power on (P0.13) → 20 ms → RST low 10 ms → high 10 ms → wait BUSY low
0x12 SW reset → wait BUSY
0x01 27 01 00     driver output: 296 gates
0x11 03           data entry: X+, Y+
0x44 00 0F        RAM X 0..15 (bytes)
0x45 00 00 27 01  RAM Y 0..295
0x3C 05           border waveform
0x21 00 80        update ctrl 1: normal RAM, source S8..S167
0x18 80           internal temperature sensor
0x4E 00 / 0x4F 00 00, 0x24 <4736 B BW>   (1 = white)
0x4E 00 / 0x4F 00 00, 0x26 <4736 B RED>  (1 = red; inverted if CONFIG_WX_EPD_RED_INVERT)
0x22 F7, 0x20     full refresh with OTP LUT → wait BUSY (≤ 40 s)
0x10 01           deep sleep → pins disconnected → power off
```

This matches the widely used 2.9" B/W/R SSD1680 sequence (GxEPD2 `GxEPD2_290_C90c`). **Verify on first bring-up:** orientation, red polarity, and how long the refresh takes (logged in the debug build).

## State machine

```
boot ─► splash "WXPAPER / WAITING FOR HOST" (only on power-on/reset-pin; skipped after WDT/fault/software reset or if battery critical)
  │
  └─► loop:
        read battery (VDDH)                      ← status flags LOW_BATT
        wx_poll(): advertise ≤ 30 s, serve one session
          NEW_IMAGE  → copy to fb, need refresh, contact
          NO_CHANGE  → contact
          NO_CONTACT → if no contact for max(3 h, 2×interval+5 min) and not yet shown: OFFLINE overlay + refresh
        battery < 3.30 V → LOW BATTERY overlay once, then no more refreshes, poll every 2 h
        refresh panel if needed
        sleep: interval (host may set 300..86400 s), or 5 min once per outage after a failed poll
              (chunked to feed the watchdog)
```

- **Overlays**: any device overlay sets `displayed_crc = 0`, so the host's next image is always accepted and replaces it.
- **Watchdog**: 3 h, keeps counting during System ON idle. The main loop feeds it every ≤ 1 h of sleep and once per loop.
- **Failure handling**: BT init failure → reboot after 60 s. Fatal error → reset (`CONFIG_RESET_ON_FATAL_ERROR`). A BUSY timeout waits up to 15 s more before cutting panel power, sets `REFRESH_FAILED` and `displayed_crc = 0` so the host resends. An image accepted but not drawn (critical battery) also reports `displayed_crc = 0`.

## Power design

- **Release build**: no UART, USB stack, logging or console. UART0, I2C0/1, PWM0 and 802.15.4 are disabled in DT.
- **SPIM2** is held resumed for the duration of `epd_show()` (so SCK/MOSI never float while CS is low) and is otherwise suspended. **SPIM2 and SAADC** use device runtime PM (`zephyr,pm-device-runtime-auto`). They are suspended outside transfers, with SPIM pins in the `low-power-enable` (disconnected) sleep state.
- **Panel**: powered only during a refresh. All panel lines are disconnected otherwise (see `hardware.md`).
- **Sleep**: plain `k_sleep()`. Zephyr idles in System ON with the RTC running, about 2–3 µA for the SoC. System OFF is not used, because it needs a GPIO/NFC/LPCOMP wake source and loses RAM.
- **BLE**:
  - Advertising: 100–150 ms interval, only during the poll window.
  - Session: the device asks for a 7.5–15 ms connection interval, 2M PHY and 251 B data length, then drops the link 150 ms after the final op. A typical session is under 1.5 s.
- **Refresh avoidance**: the host only sends a new image when its CRC differs. Content changes at most once an hour, because the image is keyed to observation time.

## Kconfig (app)

| Option | Default | Meaning |
|--------|---------|---------|
| `WX_POLL_INTERVAL_S` | 1800 | poll cadence (host can override) |
| `WX_RETRY_INTERVAL_S` | 300 | one early retry after a failed poll |
| `WX_ADV_WINDOW_S` | 30 | advertising window per poll |
| `WX_SESSION_TIMEOUT_S` | 20 | GATT inactivity timeout |
| `WX_STALE_AFTER_S` | 10800 | draw OFFLINE after this long without contact |
| `WX_LOW_BATT_MV` / `WX_CRIT_BATT_MV` | 3400 / 3300 | status flag / stop refreshing |
| `WX_CRIT_POLL_INTERVAL_S` | 7200 | poll cadence when critical |
| `WX_ROTATION` | 90 | must match host `rotate` |
| `WX_EPD_RED_INVERT` | n | panel red RAM polarity |
| `WX_EPD_BUSY_TIMEOUT_MS` | 40000 | refresh timeout |
| `WX_WDT_TIMEOUT_S` | 10800 | watchdog |
